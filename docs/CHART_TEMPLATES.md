# chart_text — формат шаблонов

Контракт на поле `chart_text` (`AnalyticsAnswer.chart_text`, `AskResponse.chart_text`).

- **Producer:** analytics-агент, фаза synthesize (`core/agent/analytics_agent/prompts.py`,
  `SYNTHESIZE_SYSTEM`). LLM решает, нужен ли график, и кладёт его сюда —
  не в `answer_text`.
- **Consumers:**
  - **Mini App** (`POST /admin/ask`) — парсит тег `[template:<id>]` и рисует
    настоящий график. Без тега падает в legacy-эвристику → тип может выбраться
    неверно.
  - **Telegram admin bot** (`presentations/telegram_admin/handlers/fallback.py`) —
    графики не рисует: срезает строку-тег и шлёт заголовок + данные как plain text.

## Формат

Если включаешь `chart_text`, первая строка ОБЯЗАТЕЛЬНО — тег шаблона в формате
`[template:<id>]`. Вторая строка — короткий заголовок (≤ 60 символов, без
префикса). Дальше — данные в формате выбранного шаблона. Пустые строки
игнорируются.

### `bar.distribution` — частоты / счётчики по категориям

Распределение одного числового показателя по 2–12 категориям (топ-темы, частота
тегов, количество сессий по дням недели и т.п.).

```
[template:bar.distribution]
Топ-5 негативних тем · 30 днів
доставка | 12
температура | 8
сервіс | 6
ціна | 4
порції | 3
```

### `bar.sentiment` — распределение по тональностям

Доля/количество positive / neutral / negative (или аналогов). Каждая строка
окрашивается: positive → emerald, negative → pink, neutral → sky, остальное →
violet. Лейбл должен начинаться со слов pos / поз / neg / нег / neu / нейтр.

```
[template:bar.sentiment]
Розподіл тональностей · 30 днів
positive | 124
neutral | 86
negative | 41
```

### `bar.grouped` — две серии бок о бок

Сравнение двух показателей по одной оси категорий (напр. pos vs neg на тему).
Формат строки: `label | +<positive> -<negative>`. Знаки `+` / `-` обязательны,
числа неотрицательные.

```
[template:bar.grouped]
Позитив vs негатив за темами · 30 днів
доставка | +8 -12
сервіс | +14 -3
страви | +22 -7
ціна | +4 -9
```

### `donut.share` — доли в общем итоге

Проценты или абсолютные числа, дающие в сумме целое (структура сегментов, доля
платящих, источники трафика). 2–6 сегментов.

```
[template:donut.share]
Частка позитиву · 30 днів
позитив | 65
негатив | 35
```

### `line.trend` — временной ряд

Динамика метрики по датам/часам. Формат строки: `<метка>: <число>`. Минимум 3
точки. Метки идут в хронологическом порядке.

```
[template:line.trend]
Sentiment по днях · 30 днів
2026-06-01: 0.32
2026-06-02: 0.45
2026-06-03: 0.41
2026-06-04: 0.58
```

### `kpi.single` — одиночное число с подписью

Одна headline-метрика, без графика как такового. Формат: заголовок → число (на
отдельной строке, можно с `%`) → подпись.

```
[template:kpi.single]
Усього сесій · 30 днів
1245
Δ +12% порівняно з попереднім періодом
```

## Правила выбора шаблона

1. Одно число без сравнения → `kpi.single`.
2. Динамика по датам/времени → `line.trend`.
3. Доли в 100% → `donut.share` (если 2–6 сегментов).
4. Распределение по positive / negative / neutral → `bar.sentiment`.
5. Сравнение двух серий по тем же категориям → `bar.grouped`.
6. Всё остальное (топы, счётчики) → `bar.distribution`.

## Ограничения

- Не используй псевдо-ASCII (`███`, `▓`, `=`) — фронт сам нарисует бары.
- Максимум 12 строк данных в `bar.*`, 6 в `donut.share`, 60 точек в
  `line.trend`. Если данных больше — оставь топ-N по релевантности.
- Если данные неполные или ты не уверен в формате — не возвращай `chart_text`
  вообще.
- Не возвращай `chart_text` без тега — фронт упадёт в legacy-эвристику и тип
  графика может выбраться неверно.
